# Research Workflow

Use this workflow whenever the user asks to research a topic and produce a report.

---

## Phase 1 — Clarify (ALWAYS run this first, no exceptions)

Before doing any research, ask the user ALL of the following questions in a single message:

1. **Topic** — What is the specific topic, question, or problem you want researched?
2. **Audience** — Who will read this report? (e.g., complete beginners, business executives, developers, general public)
3. **Depth** — Quick overview (5–10 min read) or deep dive (comprehensive, all angles)?
4. **Angles** — Are there specific sub-questions, perspectives, or aspects you want covered?
5. **Exclusions** — Anything to leave out or de-prioritize?
6. **Format** — Bullet-heavy summary, narrative sections, or executive briefing style?

Wait for the user's answers before moving to Phase 2.

---

## Phase 2 — Plan

Based on the user's answers, present a numbered research plan:
- List the 4–6 key questions you will answer
- List the types of sources you will consult (news, academic, industry reports, etc.)
- Estimate the report length

Ask the user to confirm the plan before moving to Phase 3. If they want changes, update the plan and confirm again.

---

## Phase 3 — Research

Work through each question in the research plan:
- Use web search to find current, credible information
- Collect 2–3 sources per key question
- Note the URL and a one-line description for each source
- Prioritize: official sources > reputable journalism > industry analysis > general web
- Flag anything that is contested, uncertain, or rapidly changing

---

## Phase 4 — Report

Write the final report using the template at `resources/report-template.md`.

Rules:
- Fill every section of the template
- Bullets over paragraphs (per user preference)
- Every claim that comes from a source must have a citation inline [1], [2], etc.
- Save the file to `output/YYYY-MM-DD-<topic-slug>.md` (e.g., `output/2026-06-17-electric-vehicles.md`)
- Tell the user the file path when done
